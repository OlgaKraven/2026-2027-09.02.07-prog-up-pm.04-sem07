# Охват задания и иллюстраций

Проверка выполнена по требованиям УП ПМ.04. Иллюстрации получены из реальных запусков исходной и исправленной версий сервисного стенда. Они относятся к демонстрации «Контур», а не являются доказательствами выполнения индивидуальных вариантов.

| Требование | Выполнение в методике | Доказательство и предел снимка |
|---|---|---|
| Контрольная копия и исходные данные | Подготовка baseline.json и явно заданной work-data.json; восстановление перед независимым тестом | Рис. 1 показывает начальный каталог. Путь рабочего файла, пустая история и исходные значения дополнительно сверяются по JSON. |
| D1: воспроизведение, причина, правка, повтор | Неизвестный логин; запасной выбор первого пользователя; исправление Authenticate; повтор с nobody и client | Рис. 2–4 показывают ошибочный допуск, отказ и успешное исправление ввода. Причину и изменение доказывает код, а не фотография сообщения. |
| D2: сохранение заявки при возврате | Одна единица P1, возврат, открытие P5; удаление Clear только из Back | Рис. 5–7 показывают контрольную строку, её потерю в исходной версии и сохранение в исправленной. Проверены сохранение настроек и отдельная подтверждаемая отмена. |
| D3: совместный отбор и числовая сортировка | Слово в описании, категория P1, независимые AND/OR, decimal вместо строки, второй ключ Id | Рис. 8–9 показывают четыре неправильных и две правильных позиции; числовой контрпример 1000/200. Рис. 1 показывает полный возрастающий порядок. Обратное направление и равенство стоимости имеют явные ожидания в тексте и проверки компонентов. |
| Отказ и последующее исправление поля | Сначала 3, затем отказ ещё 3; замена на 2; отказ дальнейшего превышения | Рис. 10–11 показывают сохранённые поле, исполнение и строки. Сообщение третьего добавления в рис. 11 прямо объяснено в подписи, чтобы не выдавать его за сообщение успешного действия. |
| Готовая операция заявки | P1 количеством 2 и P3 количеством 1; подтверждение, проверка файла, закрытие и запуск | Рис. 12–14 показывают две строки, успешное подтверждение и сохранённые общие остатки. Фактический JSON отдельно проверен: один заказ client, две строки, P1 3/3, P3 1/1; дата соответствует действию. |
| Перенос на собственные данные | Явные замены Id, категорий, исполнений, ожиданий; карточки всех 30 вариантов | Универсальная демонстрация не выдаётся за готовое решение вариантов. Собственные снимки и расчёты студент получает самостоятельно. |
| Контракт компонентов | Интерфейсы, входы, результаты, отсутствие изменения коллекций, адаптер | Исполняемый тест использует другую модель Sensor без переписывания алгоритма. Снимок интерфейса не заменяет эту проверку. |
| Отчёт, инструкция и сдача | Состав документов заранее дан в задании; в конце раскрыта подготовка; ссылка на проект находится в отчёте | Шаблон отчёта содержит поля результатов и доказательств. Учебные снимки не подставлены в отчёт как работа студента. |

Новые иллюстрации не расширяют задание: самостоятельно исправляются только D1–D3; проверка количества и подтверждение предоставлены готовыми. Старые торговые снимки вынесены из учебной выдачи в evidence/archive-before-2026-11-03 с сохранением байтов. Работоспособность всех индивидуальных дополнительных условий через графический интерфейс не заявляется: на всех 30 наборах выполнены проверки компонентов, а полный показ сделан на демонстрации.
